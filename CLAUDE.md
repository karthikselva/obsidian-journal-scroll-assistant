# Journal Scroll Assistant — Obsidian plugin

Companion to `D:\GitRepos\obsidian-journal-scroll` (view type `journal-scroll-view`). Same conventions as that repo: plain CommonJS, no build step, only `require("obsidian")`, mobile-safe (`requestUrl`, no Node APIs), no `innerHTML`/`el.style`/console logging, sentence-case UI. Outbound hosts: the chosen model provider, plus Wikidata and Google News for persona news (name + date only).

## Releasing

Public repo `karthikselva/obsidian-journal-scroll-assistant`. Bump `manifest.json` and add the version to `versions.json`, commit and push, then `git tag <x.y.z> && git push origin <x.y.z>` (no `v`). `.github/workflows/release.yml` attests and attaches `main.js`, `manifest.json` and `styles.css`. Don't create releases by hand. The Obsidian community directory listing is managed at community.obsidian.md → Account → Plugins.

## Hard rule: no data outside Markdown

The owner's requirement: every output lives in the daily notes or in Markdown under the journal folder. Plugin `data.json` holds **configuration only** (provider keys and models, active model, personas, areas, news toggle, context days, summaries folder). The Wikidata lookup cache is in memory only. Never cache titles, chats or results there.

- Title/highlights → frontmatter `title`, `highlights`. Comparison focus → frontmatter `focus` (area → focused|some|neglected).
- Comparisons → callouts between `%% journal-scroll-assistant: comparisons %%` and `%% /journal-scroll-assistant %%` at the end of the note. `writeComparison` replaces by persona. `cleanEntryText` strips the block and image lines before anything is sent to Gemini, so outputs never feed back in.
- Monthly timeline → `<view.dir>/<summariesFolder>/<YYYY>/<YYYY-MM> <Mon> Timeline.md`. The name does not match Journal Scroll's `DD-MM-YYYY` pattern, so it never shows up as an entry.

## Frontmatter gotcha

Many entries open with a `---` **section rule**, not frontmatter. `setFrontmatter` edits in place only when the metadata cache has real, non-empty frontmatter. Otherwise it prepends a fresh block and keeps the rule below it, then waits for the cache `changed` event so a second write doesn't prepend twice. Journal Scroll uses the same "non-empty parsed frontmatter" test to strip it.

## Architecture (`main.js`)

- `JournalScrollAssistant` attaches one `AssistantPanel` (a `Component`) per Journal Scroll view on `layout-change`/`active-leaf-change`, and re-attaches when the view rebuilt its DOM.
- `AssistantPanel` reads `view.entries` (`[{file, date}]`), `view.dir` and `view.currentPath()` from Journal Scroll (duck-typed; it falls back to scanning `view.dir`). The day in focus is `currentPath()`, falling back to the latest entry on or before today.
- The floating button opens an Obsidian `Menu`. The panel stops `keydown`/`wheel`/touch propagation, because Journal Scroll turns book pages on arrow keys.
- Chats: `newChat(key, sourcePath, contextFn)` resets the chat. `ask(text, shown, after)` loads `contextFn()` on the first turn, then sends. `after(reply)` runs inside the busy section, which is how life answers get saved. Day chats are keyed `day:<path>`, presets `<scope>:<path>`.
- Presets: `PRESETS` / `PRESET_GROUPS`, shown as chips by `showSuggestions()` and run by `askPreset()`. The scopes week, month, week-compare, month-compare and year-compare come from `periodsFor()`. The `life` scope reads every `<summaries>/**/<YYYY-MM> <Mon> Timeline.md` (minus its `## Titles` list) plus a one-line-per-day title index. Its first answer is saved to `<summaries>/<save>.md` (`saveLifeNote`) and overwritten when regenerated. Follow-up answers are not saved.
- Life areas: default `Family, Networking, Health, Career, Hobbies, Growth`. `AREA_DEFS` holds a definition for each default area, and `areaGuide()` sends them with every rating. The scale (`LEVELS`, `RATING_SCALE`) is focused / some / neglected / none, where none means "not today": neutral, used when the entry is silent. Neglected requires evidence in the entry. A saved setting equal to `OLD_DEFAULT_AREAS` (with Self-realization) migrates on load. "Re-rate life areas in a month…" calls `titleMonth(month, { rerate: true })`: every day, titles kept, focus replaced.
- Titling also rates life areas: `TITLE_SCHEMA.areas` → `focusMap()` → frontmatter `focus` (the same field compare writes; Journal Scroll renders it as tags). Batches pick days by `needsWork()` (see Batches below).
- Months: `journalMonths()` lists `{y, m, entries}`, newest first. `MonthPickerModal` (a `SuggestModal`) drives `pickTitleMonth()` (shows the untitled count per month, plus "All months" → `titleMonth("all")`) and `pickTimelineMonth()` (shows whether a timeline exists). `titleMonth`/`monthTimeline` take `{y, m}`. Never pass null to mean "all": the menu's "this month" passes `focusMonth()`, which is null when the view is empty. Batches longer than 3 get a Stop button; titles already written stay.
- Compare: the schema has a `timeline` of `{time, persona, me}` rows covering the `compareTimes` setting plus times written in the entry. `me` must be "Not in the journal" when the entry is silent. Rows are sorted client-side with `dayOrder()`, which puts times before 4 AM after 9 PM because a journal day runs past midnight, and rendered as a Time | persona | You table at the top of the callout.
- **Providers** (`PROVIDERS`): `gemini` (generateContent), `openai` and `hermes` (OpenAI-compatible `/chat/completions`; Hermes = Nous Portal, `https://inference-api.nousresearch.com/v1`) and `anthropic` (Messages API, `anthropic-version: 2026-10-21`). Settings: `providers.<id> = { enabled, apiKey, baseUrl, models[] }` and `activeModel = "<id>::<model>"`; `migrateProviders()` moves the old single `apiKey`/`model` into `providers.gemini` on load. Plain `requestUrl` HTTPS, no SDKs (no build step).
- **`llm(settings, req, onRetry, target?)`** is the only way to call a model. Requests are written in Gemini's shape (`system`, `contents` with roles user/model, optional Gemini-dialect `schema`, `thinking` low|medium|high) and translated per provider: `toChatMessages`, `toJsonSchema` (lower-case types, every field required, `additionalProperties: false`). Retries 429/5xx/529 with 2s, 5s, 12s backoff, then fails naming the model. Gemini: `thinkingConfig.thinkingLevel`, retried once without it on a thinking 400; **no `temperature`/`top_p`/`top_k`**. OpenAI-compatible: strict `json_schema` response_format, falling back on a format 400 to `json_object`, then plain text, with the schema spelled out in the system prompt. Claude: `output_config.effort` + `output_config.format` (structured outputs; forced tool use is rejected by current models), server-side refusal fallback (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`) on Opus 5.5 / Opus 5 / Fable 5.x / Sonnet 5.5, `stop_reason` refusal and max_tokens become errors. `parseJsonReply` tolerates fences and surrounding text.
- **Chat model picker**: `buildModelSelect()` in the panel header (optgroups per provider, "Set up models…" opens settings); `plugin.setActiveModel()` updates every picker. `run()` records the model, captions each answer with it (`.jsa-msg-model`), and on failure adds *Try again with [model] · Retry*, which re-runs the same `fn`.
- **Action row** (from Journal Scroll's `renderActions`): `plugin.openActionMenu(kind, evt, { view, file, onStart, anchor })` → `panel.openActionMenu`: `chat` (chat + Reflect presets), `compare` (personas, someone else, same day last month/last year, `DayPickerModal` for any same-day-of-month entry, Compare-over-time presets), `regenerate` (fill everything missing, this day, this day + saved comparisons via `regenerateDay`, a month), `summarize` (month timeline, `periodSummary("quarter"|"year")`). All take the clicked day's entry, not the day in view.
- **Day vs day**: `compareDays(entry, other)` saves a callout keyed `"<d Mon yyyy> (<gap>)"` (`describeGap`); `regenerateDay` parses that back. **Persona news**: `personOnDay(name, date)` checks Wikidata (human, P569/P570) and, if alive, `newsOnDay` reads Google News RSS for that day (pubDate from 00:00 to noon next day, deduped). Headlines go to the model numbered; `in_the_news[].ref` maps back to real links (bad refs dropped), `from_news` rows get 📰. Setting `personaNews`. Persona text must pass `looksLikeName()` (a "type a name" prompt is disarmed on `hide()`), which stops chat messages becoming personas.
- **Batches**: `needsWork(e)` = no title, no highlights, or `focus` not exactly the current areas. `generateTitle(e, { overwrite: false })` writes only the missing title/highlights, always the ratings. `titleMonth` runs 3 workers in parallel; a 401/403 stops the run. `fillEverything()` = `titleMonth("all")`.
- **Settings UI**: `TagInput` (chips + combobox; the option list is a `position: fixed` popover on `document.body` so the settings modal can't clip it; `TagInput.closeAll()` on redraw/hide) for personas (`FAMOUS_PEOPLE`), life areas (`LIFE_AREA_SUGGESTIONS`) and each provider's models (suggestions + **Load models** via `fetchProviderModels`). Each provider card has a **Test** button.

Verify by loading in a real vault. There are no tests or API mocks.
